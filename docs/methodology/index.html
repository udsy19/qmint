Methodology and evidence

Evidence kinds, response statuses, computation methods and the rules every number follows.

Principles

  • Every number carries an evidence kind. A theorem value, an SDP output, a Monte Carlo estimate and a photon measurement are never interchangeable and never shown without their label.
  • Monte Carlo is a lower bound on worst-case attack success, always with its interval. It is never presented as an upper bound or a proof.
  • Numerical SDP is not a proof unless residuals are rigorously accounted (that is CERTIFIED_NUMERIC, re-verified in exact arithmetic by lane D).
  • Simulation is not physical security. No QPU result exists in this build (gate G6 is skipped).
  • Unknown is null, never 0. An unknown bound is null / UNCERTIFIED and renders as text.
  • No theorem crosses games. W1 ≠ W1_CV ≠ W2 ≠ S1 ≠ S2 ≠ D1 ≠ A1. ε is a maximum adversary win probability, never an error bar.
  • Sources are cited to an anchor (URL plus theorem, equation or table). If a primary source could not be read, the entry says so instead of reconstructing it from memory.

Certificate statuses

Only CERTIFIED is shown in mint, and only when the frozen C5 contract allows it: assumptions met, proof reference, checker id, evidence hashes and every target bounded.

LabelKeyMeaning
CERTIFIED: Every target met by an applicable, independently checked boundCERTIFIEDEvery target met by an applicable, independently checked bound
INFEASIBLE: Applicable bounds exist but targets cannot be metINFEASIBLEApplicable bounds exist but targets cannot be met
OUT-OF-MODEL: Request violates the proof's trust/physical modelOUT_OF_MODELRequest violates the proof's trust/physical model
UNCERTIFIED: Missing bound, assumption or independent checkUNCERTIFIEDMissing bound, assumption or independent check
UNSAFE: An attack exceeds the claimed bound or targetsUNSAFEAn attack exceeds the claimed bound or targets

Response statuses

Every API response has a status. OK means a merged lane's code path produced it. The other two always carry a reason:

LabelKeyMeaning
DEMO ADAPTER: Demonstration computed from analytic / published formulas or merged lane-F/G code while the owning lane is not merged; not that lane's outputDEMO_ADAPTERDemonstration computed from analytic / published formulas or merged lane-F/G code while the owning lane is not merged; not that lane's output
NOT AVAILABLE: Nothing honest to show yet; see the reasonNOT_AVAILABLENothing honest to show yet; see the reason

Computation methods

Quantity.method disambiguates how a value was computed — for example an exact analytic value that the frozen contract labels SIMULATOR_IDEAL.

MethodMeaning
closed_forma transcribed or derived formula evaluated exactly
exact_enumerationexact model value from enumerating outcomes or Kraus operators
aer_samplingshot-sampled local Aer simulation; carries a confidence interval
event_simulationlane G discrete-event timing simulation
published_valuea number quoted from a paper
measured_dataseta statistic of a committed real measurement dataset
not_availableno value; shown as text, never as 0

Research verification statuses

Research-library entries keep the verification status from their own file — VERIFIED_FROM_SOURCE and NOT_VERIFIED per transcribed theorem field, FULL_TEXT_READ / ABSTRACT_READ / METADATA_ONLY per paper, proof statuses such as PUBLISHED_REPRODUCED per obligation. Definitions and their source files are listed under “Verification status definitions” in the research library.
